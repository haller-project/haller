# Haller-1 fingerprint expert: exact recipe of the published weights

This directory reproduces `haller-1-fingerprint.npz`, the fingerprint expert
shipped in SeedSigner (`src/seedsigner/resources/handwriting/`), from public
inputs. The fingerprint expert reads one line only: the master key
fingerprint (8 hexadecimal digits) that many users write under their words.
SeedSigner reports a seed as verified only when this fingerprint, read from
the photo, matches the fingerprint of the words; the expert is loaded when a
candidate fingerprint line is found, and the word experts are not changed.

It has the architecture of the word experts (`haller/model.py`, channels
16/32/64, 128 hidden units) and was fine-tuned from the float capitals expert
of Haller-1 in two steps, on 400,000 synthetic lines of which half are
fingerprints, plus the filtered GNHK words of the lowercase expert.

| Step | Reproduced | How |
|---|---|---|
| Synthetic shards h1-h8, validation and test lines | exactly | current `haller.generate --hex-share`, pinned versions (below) |
| Training, step 1 (epoch 1 of a 4-epoch schedule, CPU) | same level, not the same bits | float model and log published (`data/`) |
| Training, step 2 (epoch 1 of a 3-epoch schedule, GPU) | same level, not the same bits | float model and log published (`data/`) |
| Quantization | exactly, byte for byte | current `haller.quantize`, from the published float model and h1 |

## Files

| File | Content |
|---|---|
| `data/haller-1-fingerprint-step1-float.npz` | float model after step 1 (batch normalization folded), input of step 2 |
| `data/haller-1-fingerprint-float.npz` | float model after step 2, input of the quantization |
| `data/train-fingerprint-step1.log`, `data/train-fingerprint-step2.log` | their training logs (loss and EVAL score per epoch) |
| `eval_fingerprint.py` | reading of fingerprint lines by quantized weights through SeedSigner's C library |
| `SHA256SUMS.content` | content digests of the shards, the validation and test lines, the float and quantized models; SHA-256 of the shipped file |

The content digests are computed by `../haller-1/digest.py` (arrays only,
independent of the zip container of the `.npz` files):

```bash
python recipes/haller-1/digest.py --check recipes/haller-1-fingerprint/SHA256SUMS.content   # run where the files are
```

## Environment

Shards and validation lines: Python 3.12.8, numpy 2.5.5, Pillow 13.0.0
(wheel with FreeType 2.14.3 and raqm 0.11.0), embit 0.8.0, on x86-64
(Linux). These are not the versions of the other Haller-1 data (numpy 1.26.4,
Pillow 12.2.0): Pillow renders the fonts, and another version changes a few
samples.

```bash
uv venv -p 3.12.8 venv-fp
uv pip install -p venv-fp/bin/python numpy==2.5.5 pillow==13.0.0 embit==0.8.0
```

Training and quantization, as they were run:

- step 1: PyTorch 2.15.0 (CPU build), numpy 2.5.5, Python 3.12.8, on an
  x86-64 CPU, 8 threads;
- step 2 and quantization: PyTorch 2.11.0 with CUDA 13.0 (cuDNN 9.19),
  numpy 2.4.4, Python 3.14.0, on an NVIDIA RTX 3060.

The quantization gives the same file with the versions of
`requirements-lock.txt` (PyTorch 2.15.0, numpy 2.5.5, Python 3.14.0); see
[Verification](#verification).

Inputs, as in the main README:

- `FONTS`: the 287 fonts of `python -m haller.fonts FONTS`, and `CURSIVE`:
  the 115 fonts of `python -m haller.fonts CURSIVE --list data/fonts_cursive.sha256`
  (google/fonts commit `7af0d90b`, SHA-256 checked);
- `EMNIST.npz`: `python -m haller.emnist EMNIST.npz IDX_DIR --split train`
  from the official EMNIST archive (byclass train split);
- from [`recipes/haller-1`](../haller-1/README.md): `gnhk_f.npz` (the filtered
  GNHK words of the lowercase expert, regenerated by that recipe),
  `data/haller-1-capitals-float.npz` (the start of step 1) and
  `data/haller-1-eval-simulated.npz` (the simulated evaluation strips, written
  by `evalsim/regenerate.sh`).

In the commands below, `SS` is the `src` directory of the SeedSigner
checkout given in the main README, `R=recipes/haller-1-fingerprint` and
`H1=recipes/haller-1`; the commands run from the root of the repository.

## Commands

```bash
export PYTHONPATH=.:$SS
G="--emnist EMNIST.npz --bip39 data/bip39_english.txt --other data/other_words.txt"

# 1. Training shards: 8 x 50,000 lines, half of them fingerprints, seed 7000 + i
#    (h1-h6 in the 287 fonts, h7-h8 cursive in the 115 joined-script fonts; one process per shard)
for i in 1 2 3 4 5 6; do
  venv-fp/bin/python -m haller.generate $R/h$i.npz 50000 $((7000 + i)) --hex-share 0.5 --fonts FONTS $G &
done
for i in 7 8; do
  venv-fp/bin/python -m haller.generate $R/h$i.npz 50000 $((7000 + i)) --hex-share 0.5 --cursive --fonts CURSIVE $G &
done; wait

# 2. Validation and test lines, fingerprints only (not used by the training)
venv-fp/bin/python -m haller.generate $R/val_hex.npz 4000 7101 --hex-share 1.0 --fonts FONTS $G
venv-fp/bin/python -m haller.generate $R/val_cur_hex.npz 2000 7102 --hex-share 1.0 --cursive --fonts CURSIVE $G
venv-fp/bin/python -m haller.generate $R/test_hex.npz 4000 7201 --hex-share 1.0 --fonts FONTS $G

S="$R/h1.npz $R/h2.npz $R/h3.npz $R/h4.npz $R/h5.npz $R/h6.npz $R/h7.npz $R/h8.npz $H1/gnhk_f.npz"

# 3. Step 1: from the float capitals expert, epoch 1 of a 4-epoch schedule, peak learning rate 5e-4
python -m haller.train $R/step1.npz $S --eval $H1/data/haller-1-eval-simulated.npz \
    --init $H1/data/haller-1-capitals-float.npz --epochs 4 --stop-after 1 --lr 5e-4

# 4. Step 2: from step 1 (published: $R/data/haller-1-fingerprint-step1-float.npz),
#    epoch 1 of a 3-epoch schedule, peak learning rate 3e-4
python -m haller.train $R/step2.npz $S --eval $H1/data/haller-1-eval-simulated.npz \
    --init $R/data/haller-1-fingerprint-step1-float.npz --epochs 3 --stop-after 1 --lr 3e-4

# 5. Quantization of the published float model, calibrated on 3,000 lines of h1
python -m haller.quantize $R/data/haller-1-fingerprint-float.npz $R/h1.npz $R/haller-1-fingerprint.npz \
    --count 3000 --seed 1

# 6. Reading of the validation lines (SeedSigner's C library)
python $R/eval_fingerprint.py $R/val_hex.npz $R/haller-1-fingerprint.npz
python $R/eval_fingerprint.py $R/val_cur_hex.npz $R/haller-1-fingerprint.npz
```

The order of the shards on the command line matters: the training draws the
shard order and the batches from its seed (1) over the positions of the files.

**How the run was actually made.** Both steps were started for a longer
schedule and their first epoch was kept; `--stop-after 1` gives that same
epoch (the one-cycle learning-rate schedule still spans `--epochs`) without
training the others.

- Step 1 was started with `--epochs 4 --lr 5e-4 --keep-epochs` on a CPU and
  stopped during epoch 2, the machine being needed for other work; its epoch
  1 (`_e1`) is `data/haller-1-fingerprint-step1-float.npz`.
- Step 2 ran its 3 epochs (`--epochs 3 --lr 3e-4 --keep-epochs`) on the GPU.
  Epoch 1 was kept: epochs 2 and 3 read the words of the simulated strips
  less well (95.50, 91.00, 93.38 %, `data/train-fingerprint-step2.log`) and
  the fingerprint lines hardly better (81.0 and 80.3 % of validation lines
  matching, against 80.3 %; see [Results](#results)).
  Its epoch 1 is `data/haller-1-fingerprint-float.npz`.

The EVAL score printed by `haller.train` is the reading of BIP39 words by
the fine-tuned model; it checks that the model still reads words, not that
it reads fingerprints, which `eval_fingerprint.py` measures. The real score
is 0.00 % because the published strips have no real photos.

## Results

Validation lines (first 2,000 of each file), quantized weights, through
SeedSigner's C library; "match": the true fingerprint has a probability of at
least 1e-4, the threshold at which SeedSigner accepts it; "exact": the 8 most
probable digits are the right ones.

| Weights | Printed lines: match | exact | Cursive lines: match | exact |
|---|---|---|---|---|
| Haller-1 word experts only (capitals + lowercase) | 43.4 % | 9.2 % | 29.3 % | 6.9 % |
| `haller-1-fingerprint.npz` (published) | 80.3 % | 34.6 % | 69.1 % | 34.3 % |
| Step 2, epoch 2 (not kept) | 81.0 % | 37.4 % | | |
| Step 2, epoch 3 (not kept) | 80.3 % | 36.9 % | | |
| Retrained with this recipe (`--deterministic`, see [Verification](#verification)) | 81.3 % | 37.0 % | 71.8 % | 37.4 % |

Printed lines: `val_hex.npz` (287 fonts and EMNIST letters); cursive lines:
`val_cur_hex.npz` (115 joined-script fonts). SeedSigner reads the
fingerprint line with the fingerprint expert alone; averaged with the two
word experts, the match rate is 2 to 3 points lower. These lines are
simulated; the decision rule of SeedSigner (zero false verified seed) is
measured on whole pages by the engine, not here.

## Verification

All the files of the table at the top were checked against the originals
of the Haller-1 fingerprint expert:

- **Data**: the 8 shards and the 3 validation and test files, regenerated
  with the commands above, the code of this repository, the environment
  above, fonts downloaded by `haller.fonts` and EMNIST converted from the
  official archive, on a cloud x86-64 machine: the same content digests as
  the originals (`SHA256SUMS.content`), all 11.
- **Quantization** (step 5) of the published float model with h1: the
  shipped file, byte for byte (SHA-256 `b92cca55…`), on the machine that made
  it, with the versions of the original run and with those of
  `requirements-lock.txt`. On another processor (Intel Xeon, PyTorch 2.15.0
  for the CPU), the calibrated ranges differ in their last bits and the file
  differs; with `--ranges` set to the shipped file, it is the shipped file
  byte for byte. Same behaviour as the word experts (see
  [`recipes/haller-1`](../haller-1/README.md#quantization)).
- **Training**: steps 3 and 4 run again with `--deterministic` on an RTX
  3060 (PyTorch 2.11.0, CUDA 13.0), from the published capitals float model
  and the original data, then quantized and read by `eval_fingerprint.py`.
  Step 1: loss 1.0939 against 1.0930, words of the simulated strips 95.51 %
  against 95.30 %; step 2: loss 1.0647 against 1.0696, words 94.56 % against
  95.50 %. The retrained expert reads the fingerprint lines at the same
  level (81.3 % against 80.3 % of printed lines matching, 71.8 % against
  69.1 % of cursive lines; table in [Results](#results)). It is not the
  published model and has not been measured on whole pages.

## Training

The training is not bit-reproducible as it was run: step 2 used
`torch.backends.cudnn.benchmark` and the CUDA CTC loss, whose backward pass is
not deterministic, and step 1 ran on a CPU with 8 threads. The two float
models are therefore published, and step 5 gives the shipped weights exactly
from the second one. `haller.train --deterministic` makes new runs
bit-identical on the same hardware and software; a retrained model reaches
the same level, not the same weights, and must be measured again (fingerprint
lines and the whole engine, with zero false verified seeds) before it
replaces the published one.
